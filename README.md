# CRM LOOP

고객 생애주기 캠페인을 기획하고 효과를 재는 포트폴리오입니다. 첫 방문을 만드는 캠페인, 관계를 깊게 하는 행사, 다시 오게 하는 메시지를 같은 기준으로 설계하고 측정합니다.

## 30초 안내

- **문제:** CRM 캠페인은 반응률로 성과를 말하기 쉽습니다. 그러나 반응한 고객 중 상당수는 메시지가 없어도 샀을 고객입니다. 누구에게 보내야 반응이 *늘어나는지*, 그 증분이 비용을 넘는지를 따로 재야 합니다.
- **사례 A, 상시 캠페인:** 공개 이메일 실험 데이터 64,000명으로 증분 효과, 고객군별 효과, 업리프트 모델, 예산 계산을 했습니다.
- **사례 B, VIP 행사:** 가상 VIP 프리뷰(SCENT LOOP)에서 초청 이유, 참석, 동의, 후속 업무가 끊기지 않도록 운영 흐름과 웹 화면을 만들었습니다.
- **사례 C, 비수기 체류 캠페인:** 가상 숙박 브랜드의 봄, 가을 주중 1박 캠페인(리셋 미드위크)을 기획하고, 할인 제안과 비교할 수 있는 세 군 실험까지 설계했습니다.
- **공통 기준:** 세 사례가 같은 [KPI 정의서](docs/KPI.md)와 동의 기준을 씁니다. 열람은 반응으로 세지 않고, 비교군이 없으면 `효과`라고 부르지 않습니다.

### 사례 B: SCENT LOOP

가상의 탬버린즈 카디퓨저 프라이빗 프리뷰입니다. 현장에서 고른 향을 후속 상담, 예약과 재방문으로 이어가는 흐름을 뜻하며, 실제 브랜드가 사용한 행사명은 아닙니다.

**초청, 현장 경험, 마케팅 동의, 후속 상담과 재방문**

| 단계 | 관리할 정보 | 판단의 목적 |
|---|---|---|
| 행사 전 | 고객군별 초청 이유, 제외 조건과 담당자 | 누구를 왜 초대하는지 설명합니다. |
| 현장 | 참석 여부, 제품과 향에 대한 관심, 상담 요청 | 참석 수와 실제 관심을 구분합니다. |
| 동의 | 행사 참석과 별도로 확인한 마케팅 수신 동의 | 후속 연락이 가능한 조건을 분명히 합니다. |
| 행사 후 | 다음 행동, 담당자, 기한과 완료 근거 | 상담 및 예약 요청이 인계 과정에서 빠지지 않게 합니다. |

가상 초청 고객 240명을 기존 우수 및 재구매 고객 70명, 고관여 잠재 고객 80명, 콘텐츠 크리에이터 30명, 휴면 VIP 60명으로 나눴습니다. 계산용 흐름은 초청 240명, 참석 의사 응답 156명, 방문 확정 132명, 참석 116명, 체험 104명, 마케팅 동의 82명, 후속 반응 47명, 관계 행동 28명입니다. **이 수치는 가상 데이터이며 실제 행사 성과가 아닙니다.** 고객군 정의는 [기획안](docs/PROJECT-PLAN.md)에 있습니다.

### 사례 C: 리셋 미드위크

호텔과 리조트를 여러 지역에서 운영하는 가상의 숙박 브랜드에서, 봄과 가을의 주중 1박을 지점별 계절 체험과 멤버십 재방문 혜택으로 잇는 자사몰 캠페인입니다. 고객이 동행 형태, 여행 목적, 선호 활동 세 가지를 고르면 지점과 체험 조합을 추천하고, 체크아웃 뒤 남긴 다음 여행 희망 시기를 다음 캠페인의 발송 시점으로 씁니다.

"할인보다 맞춤 제안이 낫다"는 주장을 확인하기 위해 맞춤 제안군, 할인 제안군, 미발송군으로 무작위 배정하고, 증분 예약률과 180일 재예약률을 사례 A와 같은 방법으로 재도록 설계했습니다. 같은 메시지도 받는 사람에 따라 효과가 크게 다르다는 사례 A의 결과가 제안을 나누는 근거입니다. **모든 고객군과 수치는 가상 예시이며, 실제 회사의 캠페인이나 데이터가 아닙니다.** 자세한 내용은 [기획안](docs/CASE-C-SEASONAL-STAY.md)에 있습니다.

## 데이터와 근거의 경계

| 구분 | 내용 | 표시 |
|---|---|---|
| 공개 실제 데이터 | Hillstrom 이메일 실험 (2008, 미국 온라인 소매) | 사례 A의 증분 효과, 업리프트, 표본 수 |
| 가정값 | 마진율, 발송 비용, 쿠폰율 | 사례 A 예산 계산, 민감도 표로 범위 제시 |
| 가상 데이터 | 초청 고객 수와 퍼널, 숙박 고객군 | 사례 B, 사례 C |
| 설계 제안 | 동의 모델, 접촉 정책, 측정 계획, 세 군 실험 | 공통, 사례 C |

원문 데이터와 API 키는 저장소에 넣지 않습니다. 실제 회사의 고객 자료나 제가 집행한 캠페인의 성과는 포함하지 않습니다.

## 남은 검증과 한계

- 사례 A는 2008년 미국 데이터이고 관찰 기간이 2주입니다. 지금의 채널 환경이나 다른 업종에 그대로 옮길 수 없습니다.
- 수신거부율은 공개 데이터에 없어 `미측정`입니다. 증분 이익이 양수여도 수신거부가 늘면 판단이 바뀔 수 있습니다.
- 여성용 메일에서 하위 고객을 빼는 판단은 이익 차이가 신뢰구간 안에 있어 다음 실험으로 확인할 가설입니다.
- 사례 B는 가상 데이터라 초청 기준과 후속 행동이 재방문을 늘리는지 검증하지 못했습니다.
- 사례 C는 기획과 실험 설계까지입니다. 봄, 가을 주중 수요가 실제로 비어 있는지, 지점별 체험을 운영할 수 있는지는 내부 데이터와 운영 담당자 확인이 필요합니다.
- 다음 작업: 2차는 실제 거래 데이터(Online Retail II)로 코호트 리텐션, RFM, CLV를 만들고, 3차는 웹 `캠페인 측정` 화면과 Journey 설계도, 캠페인 브리프를 만듭니다. 범위와 순서는 [제품 기획서](docs/PRD.md)에 있습니다.

## 실행

**사례 A 분석** (Python 3.12 이상)

```sh
python -m venv .venv
.venv/Scripts/python -m pip install -r analysis/requirements.txt
.venv/Scripts/python -I analysis/fetch_data.py
.venv/Scripts/python -I analysis/hillstrom.py
.venv/Scripts/python -I analysis/report.py
.venv/Scripts/python -m pytest analysis/tests
```

macOS와 Linux에서는 `.venv/Scripts/python`을 `.venv/bin/python`으로 바꿉니다.

**사례 B 웹 화면** (Node.js 22 이상)

```sh
npm ci
npm start
```

터미널에 표시된 주소를 브라우저로 엽니다. 서울시 데이터 연결 설정은 [실행 안내](docs/RUNNING.md)를 참고하세요.

```sh
npm test
npm run build
node verify-worker.mjs
```
