# CRM LOOP / PRD

- 버전: v2.0 초안 (2026-10-19)
- 이전 판: v1 `Global CRM Event Operations` (SCENT LOOP 단일 사례). git 기록에 남아 있습니다.
- 상태: 검토 중. 확정 전에는 코드를 바꾸지 않습니다.

## 0. v1에서 바뀐 점

| 구분 | v1 (SCENT LOOP) | v2 (CRM LOOP) |
|---|---|---|
| 범위 | 향 브랜드 VIP 행사 1건 | 상시 캠페인과 행사를 같은 기준으로 운영 |
| 데이터 | 가상 고객 240명 | 공개 실제 데이터 2종 + 기존 가상 사례 |
| 효과 | 측정하지 않음 | 무작위 실험 데이터로 캠페인 덕분에 늘어난 효과(증분)를 측정 |
| 대상 선정 | 고객군별 선정 이유를 가정 | 보내면 반응이 달라지는 고객을 모델로 고르고 예산까지 계산 |
| 직무 연결 | 특정 공고의 업무 표 | 업종과 회사에 묶이지 않는 범용판. 공고별 내용은 저장소에 넣지 않음 |

SCENT LOOP는 지우지 않고 **사례 B**로 남깁니다. 동의 모델, KPI 정의 규칙, 누락 업무 관리는 두 사례가 함께 쓰는 **공통 운영 기준**으로 올립니다.

## 1. 제품 요약

CRM 캠페인과 고객 행사에서 **누구에게, 왜, 얼마까지 연락할지**를 실제 데이터로 정하고, 연락한 뒤에는 **같은 기준으로 효과를 재는** CRM 운영 모델입니다.

- **사례 A, 상시 캠페인 (대표 사례, 새로 만듦):** 공개 거래 데이터와 이메일 실험 데이터로 이탈 시점을 찾고, 고객 가치를 예측하고, 캠페인 덕분에 늘어난 효과가 큰 고객에게만 예산을 씁니다.
- **사례 B, VIP 행사 (기존 SCENT LOOP):** 오프라인 행사에서 초청 이유, 참석, 동의, 후속 업무가 빠지지 않게 운영합니다.
- **공통 운영 기준:** KPI 정의서, 동의 모델, 접촉 정책, 근거 표시 규칙.

## 2. 해결할 문제

CRM 성과를 반응률로만 보면 다음 세 가지를 놓칩니다.

1. **보내지 않았어도 샀을 고객에게 비용을 쓴다.** 쿠폰을 받은 우수 고객이 구매해도, 쿠폰 덕분인지는 알 수 없습니다.
2. **고객이 언제 떠나는지 모른 채 발송 시점을 정한다.** 첫 구매 뒤 몇 달째에 이탈이 몰리는지 모르면 재방문 캠페인이 늦거나 이릅니다.
3. **행사와 캠페인의 성과를 서로 다른 기준으로 센다.** 분모, 기간, 반응의 정의가 다르면 두 활동을 비교할 수 없습니다.

## 3. 사용자와 협업자

| 역할 | 이 모델에서 얻는 것 |
|---|---|
| CRM 담당자 | 대상 고객 목록과 선정 근거, 발송 시점, 접촉 제한 |
| 마케팅 기획 | 캠페인 브리프 1장(목표, 대상, 메시지, 지표, 측정 방법) |
| 데이터 분석 협업자 | 재현 가능한 분석 코드와 지표 정의서 |
| 개인정보, 법무 | 동의 항목, 수신거부 처리, 보관 원칙 |
| 리테일, 이벤트 운영 | 사례 B의 현장 기록 항목과 인계 기준 |

## 4. 목표와 제외 범위

### 목표

1. 첫 구매 이후 이탈이 몰리는 시점을 실제 거래 데이터로 찾는다.
2. 고객을 최근성, 빈도, 금액(RFM)으로 나누고, 앞으로의 가치(CLV)를 예측해 **가치와 이탈 위험의 두 축**으로 본다.
3. 무작위 실험 데이터로 캠페인의 평균 증분 효과와 고객군별 증분 효과를 측정한다.
4. 보내면 반응이 달라지는 고객을 고르는 업리프트 모델을 만들고, 무작위 선정보다 나은지 검증용 데이터로 확인한다.
5. 발송 비용과 혜택 비용을 넣어 **상위 몇 %까지 보내야 증분 이익이 가장 큰지** 계산한다.
6. 캠페인 Journey, 접촉 빈도 제한, 동의 처리까지 운영 설계로 정리한다.
7. 사례 A와 사례 B가 같은 KPI 정의서를 쓴다.

### 제외 범위

- 특정 회사나 공고에 맞춘 내용 (지원할 때 따로 만드는 적용 예시 1쪽은 저장소에 넣지 않음)
- 실제 메시지 발송, 실제 고객 데이터, 실제 Marketing Cloud 계정 설정
- 두 공개 데이터의 고객을 합치는 분석 (서로 다른 회사의 고객입니다)
- 공개 데이터에 없는 지표의 추정 (예: 수신거부율. 정의만 두고 `미측정`으로 표시)
- 효과 예측치를 실제 성과처럼 쓰는 표현

## 5. 데이터와 근거의 경계

| 자료 | 내용 | 쓰는 곳 | 쓰지 않는 곳 | 저장소 정책 |
|---|---|---|---|---|
| UCI Online Retail II | 영국 온라인몰 실제 거래 기록 (2009-12 ~ 2011-12, CC BY 4.0) | 코호트 리텐션, RFM, CLV, 월별 변동 | 캠페인 효과 (실험이 아님) | 원문은 커밋하지 않고 내려받기 스크립트만 둠 |
| Hillstrom 이메일 실험 (MineThatData, 2008) | 고객 약 6.4만 명을 남성용 메일, 여성용 메일, 미발송으로 무작위 배정하고 2주간 방문, 구매, 구매 금액을 기록 | 평균 증분 효과, 고객군별 증분, 업리프트 모델, 예산 계산 | CLV (구매 이력이 요약값뿐) | 원문은 커밋하지 않음. 라이선스 표기를 내려받을 때 다시 확인 |
| SCENT LOOP 가상 데이터 | 가상 초청 고객 240명과 퍼널 | 사례 B의 운영 구조와 계산 검산 | 실제 성과 주장 | 기존대로 유지, `가상` 표시 |
| 비용 가정 | 발송 단가, 혜택 비용, 마진율 | 예산 계산 | 실제 단가 주장 | 화면에서 바꿀 수 있는 입력값으로 두고 기본값의 근거를 적음 |

데이터 건수, 기간, 라이선스는 내려받은 뒤 실제 파일로 다시 확인하고 이 표를 고칩니다.

## 6. 전체 구조

```text
공통 운영 기준 (KPI 정의서, 동의 모델, 접촉 정책, 근거 표시)
├─ 사례 A. 상시 캠페인
│   1단계 문제 찾기    코호트 리텐션, 월별 변동          (Online Retail II)
│   2단계 고객 나누기  RFM, CLV, 가치와 이탈 위험 지도    (Online Retail II)
│   3단계 효과 측정    평균 증분, 고객군별 증분, 업리프트, 예산 계산 (Hillstrom)
│   4단계 운영 설계    Journey, 빈도 제한, 동의와 수신거부
└─ 사례 B. VIP 행사 (SCENT LOOP)
    선정, RSVP, 체크인, 체험, 동의, 후속, 관계 행동
```

두 데이터는 고객이 다르므로, 2단계의 고객 지도와 3단계의 대상 선정 규칙은 각자의 데이터에서 따로 검증합니다. 둘을 합친 운영 규칙(예: 가치가 높고 이탈 위험이 큰 고객 중 업리프트 상위만 발송)은 **설계 제안**으로 표시합니다.

## 7. 사례 A 상세

### 1단계. 문제 찾기

- 첫 구매 월 기준 코호트를 만들고, 1~12개월 차 재구매 비율을 계산합니다.
- 이탈이 가장 크게 일어나는 구간을 찾고, 그 구간을 재방문 캠페인의 발송 시점 후보로 둡니다.
- 월별 매출과 구매 고객 수의 변동으로 비수기를 찾습니다. 비수기는 캠페인 시점 판단의 보조 근거로만 씁니다.

### 2단계. 고객 나누기

- RFM 점수로 고객군을 나누고, 고객군마다 **선정 이유와 제외 조건**을 적습니다 (SCENT LOOP 방식).
- BG/NBD와 Gamma-Gamma 모델로 향후 구매 횟수와 금액을 예측해 CLV를 구합니다.
- 기간을 나눠(앞 기간으로 학습, 뒤 기간으로 확인) 예측이 실제 구매와 얼마나 맞는지 검증합니다.
- 가치(CLV)와 이탈 위험(활동 확률)으로 4분면 지도를 만듭니다. 사례 B의 `휴면 VIP` 가정을 이 지도에서 실제로 확인합니다.

### 3단계. 효과 측정

- **평균 증분 효과:** 메일별로 발송군과 미발송군의 방문률, 구매율, 1인당 구매 금액 차이와 신뢰구간.
- **고객군별 증분 효과:** 최근성, 과거 구매 금액, 신규 여부, 채널별로 나눠 효과 차이를 봅니다.
- **업리프트 모델:** 두 모델 방식(발송군과 미발송군을 따로 학습)을 기준선으로 두고, 학습용과 검증용으로 나눈 데이터에서 Qini 곡선으로 무작위 선정과 비교합니다. 다른 방식은 기준선보다 나을 때만 채택합니다.
- **예산 계산:** 업리프트 순위 상위 k%에게 보낼 때의 증분 이익을 계산합니다.
  - 증분 이익 = 증분 매출 x 마진율 - 발송 비용 - 혜택 비용
  - 비용 가정을 바꾸면 최적 k가 어떻게 움직이는지 민감도 표를 함께 냅니다.
- **측정 계획 템플릿:** 다음 캠페인을 위한 홀드아웃 비율과 필요한 표본 수 계산.

### 4단계. 운영 설계

- Journey 설계도: 진입 조건, 대기 기간, 분기(반응, 무반응), 종료 조건. Marketing Cloud Journey Builder 용어로 적되, 실제 계정 설정은 하지 않습니다.
- 접촉 정책: 고객 1명당 기간별 최대 발송 수, 무반응 시 휴면 처리 기준, 수신거부 즉시 제외.
- 동의 모델: 목적, 채널, 동의 시각, 정책 버전 (사례 B의 FR-05를 공통 기준으로 올림).
- 캠페인 브리프 1장: 목표, 대상과 선정 근거, 제외 대상, 메시지, 발송 시점, 북극성 지표, 보조 지표, 측정 방법.

## 8. 공통 운영 기준

### KPI 정의서

모든 지표에 이름, 분자, 분모, 기간, 중복 제거 기준, 데이터 출처, 측정 상태(측정, 미측정, 분모 0)를 둡니다.

| 지표 | 분자 | 분모 | 쓰는 곳 |
|---|---|---|---|
| 북극성: 90일 재구매율 | 기준일 이후 90일 안에 다시 구매한 고객 | 기준일 이전 구매 고객 | 사례 A 1, 2단계 |
| 증분 구매율 | 발송군 구매율 - 미발송군 구매율 | 각 군의 배정 고객 | 사례 A 3단계 |
| 1인당 증분 매출 | 발송군 1인당 매출 - 미발송군 1인당 매출 | 각 군의 배정 고객 | 사례 A 3단계 |
| 증분 이익 | 7장의 식 | 발송 대상 수 | 사례 A 3단계 |
| 후속 반응률 | 클릭, 회신, 상담 요청 고객 (열람 제외) | 마케팅 동의 고객 | 사례 B |
| 수신거부율 (보호 지표) | 수신거부 고객 | 발송 고객 | 공통, 공개 데이터에서는 `미측정` |

### 근거 표시

공개 실제 데이터, 가상 데이터, 가정값, 설계 제안을 화면과 문서에서 서로 다른 표시로 구분합니다.

## 9. 기능 요구사항

### 사례 B (기존 유지)

v1의 FR-01 ~ FR-10(고객 선정, RSVP, 체크인, 체험과 서비스 복구, 동의, 후속, 누락 업무, 성과 계산, 글로벌 운영, 근거와 결과물)을 유지합니다. FR-05(동의)와 FR-08(성과 계산)은 8장의 공통 기준으로 옮기고, 사례 B는 이를 참조합니다.

### 사례 A (새로 추가)

- **FR-11 데이터 준비:** 내려받기 스크립트가 원문을 받아 해시를 확인하고 정제합니다. 원문과 정제본은 git에서 제외합니다.
- **FR-12 코호트 리텐션:** 첫 구매 월별 1~12개월 차 재구매 비율 표와 그림을 만듭니다.
- **FR-13 RFM과 CLV:** 고객군 정의, 고객군별 선정 이유와 제외 조건, CLV 예측과 기간 분리 검증 결과를 냅니다.
- **FR-14 증분 효과:** 메일별 평균 증분 효과와 신뢰구간, 고객군별 증분 효과를 냅니다.
- **FR-15 업리프트 모델:** 학습용과 검증용 분리, Qini 곡선, 무작위 선정 대비 결과를 냅니다.
- **FR-16 예산 계산:** 비용 가정을 입력값으로 받아 상위 k%별 증분 이익과 민감도 표를 냅니다.
- **FR-17 결과 내보내기:** 분석 결과를 `analysis/results/*.json`으로 저장하고, 웹 화면과 PDF, Excel이 같은 파일을 읽습니다.
- **FR-18 웹 화면:** 기존 웹앱에 `캠페인 측정` 화면을 추가합니다. 비용 가정을 바꾸면 증분 이익과 최적 k가 다시 계산됩니다.
- **FR-19 운영 설계 문서:** Journey 설계도, 접촉 정책, 캠페인 브리프를 `docs/`에 둡니다.

| 검사 | 기존 `npm test` + Python 테스트, GitHub Actions에 둘 다 추가 | 보고서 숫자와 분석 결과가 다르면 실패하게 |

## 11. 완료 기준

- 내려받기부터 결과 JSON까지 명령 하나로 다시 만들 수 있다.
- README, PDF, Excel, 웹 화면의 핵심 숫자가 같은 JSON에서 나오고, 자동 검사로 일치를 확인한다.
- 모든 지표가 KPI 정의서에 분자, 분모, 기간과 함께 있다.
- 업리프트 모델은 검증용 데이터에서 무작위 선정과 비교한 결과를 낸다. 무작위보다 낫지 않으면 그 결과를 그대로 적는다.
- CLV 예측은 기간 분리 검증 결과를 함께 적는다.
- 예산 계산은 비용 가정과 민감도 표를 함께 보여 준다.
- 원문 데이터, 정제본, API 키가 저장소에 없다.
- 공개 실제 데이터, 가상 데이터, 가정값, 설계 제안이 구분되어 표시된다.
- 특정 회사 이름이나 공고 문구가 README와 PRD에 없다 (사례 B의 브랜드 이름은 가상 사례 설명으로만 남김).
