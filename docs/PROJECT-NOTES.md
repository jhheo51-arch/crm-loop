# 사례 B SCENT LOOP 기획 판단과 검증 과제

[프로젝트 소개로 돌아가기](../README.md)

## 왜 만들었나

팝업이 끝난 뒤 다음과 같은 정보가 사라지기 쉽다고 생각했습니다.

- 누구를 왜 초대했는가
- 예약한 고객이 실제로 왔는가
- 현장에서 어떤 제품과 향에 관심을 보였는가
- 연락에 동의했는가
- 상담이나 예약 요청을 누가 언제 처리해야 하는가
- 행사 후 구매와 재방문을 어떤 기준으로 셀 것인가

이 질문을 확인할 수 있도록 행사 전의 초청 이유와 행사 후 담당 업무가 이어지는 표를 먼저 만들었습니다.

## 대표 기획안: SCENT LOOP

SCENT LOOP는 제가 붙인 프로젝트 이름입니다. `SCENT`는 현장에서 고른 향, `LOOP`는 그 선택이 상담/예약/재방문으로 이어지는 과정을 뜻합니다. 공개 자료를 참고한 브랜드가 실제로 사용한 행사명은 아닙니다.

가상 초청 고객 240명을 다음 네 그룹으로 나눴습니다.

- 기존 우수, 재구매 고객 70명
- 카디퓨저와 자동차 생활에 관심을 보인 잠재 고객 80명
- 브랜드와 맞는 콘텐츠 크리에이터 30명
- 과거 구매 뒤 최근 반응이 없는 VIP 60명

초청, RSVP, 방문 확정, 참석, 체험, 마케팅 동의, 후속 반응, 상담/예약/구매를 각각 다른 단계로 셌습니다. 행사 참석과 마케팅 수신 동의도 분리했습니다.

## 제가 확인하고 정한 것

1. 브랜드 공식 자료, 행사 자료, 공개 방문 후기를 역할별로 나눠 읽었습니다.
2. 대기, 품절, 체험 마감 사례를 현장 기록 항목과 후속 업무에 반영했습니다.
3. 전환율이 좋아 보이게 분모를 바꾸지 않도록 계산 기준을 먼저 정했습니다.
4. 직접 확인하지 못한 내용과 가상 수치는 문서마다 표시했습니다.
5. 서울시 공공데이터와 Open-Meteo를 연결해 장소와 행사 시간대의 운영 조건도 함께 볼 수 있게 했습니다.

기획 범위와 판단 기준을 먼저 정한 뒤 웹 화면과 문서를 구현했고, 문구, 계산식, 화면을 다시 확인했습니다.

공개된 관련 글을 모두 수집한 전수 조사는 아닙니다. 2026-10-07에 접근할 수 있었고 대표 기획안에 직접 필요한 자료를 선별했습니다. 실제 고객 수, 매출, 초청 기준과 내부 CRM 시스템은 확인하지 못했습니다.

## 공개 후기를 사용한 기준

- 공식 자료는 행사 시기와 브랜드가 공개한 의도를 확인하는 데만 사용했습니다.
- 개인 후기는 한 사람이 특정 시점에 겪은 경험으로만 기록했습니다.
- 제가 직접 방문한 것처럼 표현하지 않았습니다.
- 후기 한 건을 전체 고객의 공통 불편으로 확대하지 않았습니다.
- 작성자의 이름과 계정 정보는 고객 데이터로 수집하지 않았습니다.

## 아직 확인하지 못한 것

- 실제 회사의 고객 등급, 국가별 동의 기준과 사용 중인 CRM 구조
- 실제 행사 현장에서 기록할 수 있는 정보의 양과 담당자 부담
- 초청 기준과 후속 행동이 재방문, 상담과 구매에 미치는 효과
- 실무자 검토 후 유지, 수정 또는 삭제해야 할 항목

## 이 프로젝트에서 하지 않은 것

- 실제 고객 명단이나 브랜드 내부 데이터를 사용하지 않았습니다.
- 실제 초청장 발송, 회원 가입, 결제는 진행하지 않았습니다.
- 가상 전환율을 실제 행사 성과로 제시하지 않습니다.
- 실제 적용 전에는 회사의 고객 정의, 국가별 개인정보, 광고 규정, 현장 담당자의 확인이 필요합니다.
